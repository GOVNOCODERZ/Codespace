# Ответы на контрольные вопросы (Лабораторная работа №4)

### 1. Охарактеризуйте Intel oneTBB.
**Intel oneAPI Threading Building Blocks (oneTBB)** — кроссплатформенная библиотека шаблонов C++ для параллельного программирования на системах с общей памятью (поддерживает Windows, Linux, macOS и др.).

Основные особенности:
- Позволяет абстрагироваться от низкоуровневого управления потоками ОС и описывать параллелизм на уровне логических задач (*task parallelism*), которые «легче» потоков ОС.
- Автоматически адаптируется к аппаратной платформе и балансирует нагрузку между потоками за счёт механизма перехвата работы (*work stealing*), обеспечивая высокую масштабируемость.
- Все компоненты размещены в пространстве имён `tbb` (или `oneapi::tbb`).

В состав библиотеки входят:
- шаблоны параллельных алгоритмов (`parallel_for`, `parallel_reduce`, `parallel_invoke`, `parallel_sort`, `parallel_for_each`, `parallel_scan`, `parallel_pipeline`);
- вычислительный граф (*Flow Graph*);
- потокобезопасные контейнеры (`concurrent_vector`, `concurrent_queue`, `concurrent_hash_map`);
- примитивы синхронизации (мьютексы, атомарные операции);
- масштабируемые аллокаторы памяти (`scalable_allocator`, `cache_aligned_allocator`), локальная память потока (TLS) и планировщик задач.

---

### 2. Как можно узнать максимальное количество потоков которые будут созданы по умолчанию в oneTBB?
Нужно подключить заголовок `#include <tbb/info.h>` (или `#include <oneapi/tbb/info.h>`, либо общий `<tbb/tbb.h>`) и вызвать функцию:

```cpp
int num_threads = tbb::info::default_concurrency();
```

Она возвращает максимальное число потоков, которое будет создано по умолчанию для неявной или явной арены задач (`task_arena`). Текущее действующее глобальное ограничение можно дополнительно проверить вызовом:

```cpp
size_t allowed = tbb::global_control::active_value(
    tbb::global_control::max_allowed_parallelism);
```

---

### 3. Каким образом в Intel oneTBB происходит управление потоками?
По умолчанию oneTBB скрывает явное создание и завершение потоков: библиотека сама поддерживает пул рабочих потоков и распределяет по ним задачи с помощью планировщика (*work stealing*).

Если требуется явно ограничить число потоков, применяются два механизма:
- **Глобальное управление** через объект `tbb::global_control` (действует по принципу RAII до выхода объекта из области видимости):
  ```cpp
  tbb::global_control global_limit(
      tbb::global_control::max_allowed_parallelism, num_threads);
  ```
- **Локальное управление** через арены задач (`tbb::task_arena`), позволяющие задать число потоков и изолировать вычисления для конкретного фрагмента кода с помощью `arena.execute([&]{ ... })`, не меняя глобальный лимит для остального приложения.

### 4. Дайте понятие диапазона (Range), какие типы моделей диапазона доступны в oneTBB?
**Диапазон (*Range*)** — это абстракция пространства итераций, которую можно рекурсивно делить на две части для параллельной обработки разными потоками.

Разделение выполняется через конструкторы разбиения:
- **базовый конструктор разбиения** (`Range(r, tbb::split)`) — обычно делит диапазон примерно пополам;
- **конструктор пропорционального разбиения** (`Range(r, tbb::proportional_split&)`, опциональный, активируется флагом `is_splittable_in_proportion = true`) — делит диапазон в заданной пропорции.

У диапазона также задаётся минимальный неделимый размер блока `grainsize` (по умолчанию `1`) и методы `begin()`, `end()`, `size()`, `empty()`, `is_divisible()`.

Доступные в oneTBB модели диапазона:
- `blocked_range<Value>` (`<tbb/blocked_range.h>`) — одномерный диапазон;
- `blocked_range2d<RowValue, ColValue>` (`<tbb/blocked_range2d.h>`) — двумерный диапазон;
- `blocked_range3d<PageValue, RowValue, ColValue>` (`<tbb/blocked_range3d.h>`) — трёхмерный диапазон;
- `blocked_rangeNd<Value, N>` (`<tbb/blocked_rangeNd.h>`) — N-мерный диапазон.

### 5. Охарактеризуйте oneTBB parallel_for.
`tbb::parallel_for` (`#include <tbb/parallel_for.h>`) — шаблон параллельного алгоритма, разбивающий пространство итераций цикла на блоки (*chunks*), которые независимо обрабатываются разными потоками.

Основные формы вызова:
1. **Индексная форма:** `parallel_for(first, last, [step,] f [, partitioner[, group]])` — параллельный аналог цикла `for (auto i = first; i < last; i += step) f(i);`.
2. **Диапазонная форма:** `parallel_for(range, body [, partitioner[, group]])` — принимает модель диапазона (`blocked_range`, `blocked_range2d` и др.) и тело обработки в виде лямбда-выражения или функционального объекта (класса с `void operator()(const Range& r) const`).

---

### 6. Поясните аспекты управления распределением работы oneTBB parallel_for.
Распределение итераций между потоками регулируется размером блока `grainsize` (задаёт предел дробления диапазона) и выбором **разделителя (*partitioner*)**:
- `simple_partitioner()` — рекурсивно делит диапазон на максимально возможную глубину (до размера `grainsize`). Выбор подходящего `grainsize` для баланса между параллелизмом и накладными расходами лежит на программисте.
- `auto_partitioner()` *(по умолчанию)* — динамически подбирает глубину разбиения с учётом числа потоков и перехвата задач, автоматически балансируя нагрузку без ручного подбора `grainsize`.
- `affinity_partitioner` — запоминает, какие потоки выполняли предыдущие блоки итераций, и при повторных вызовах старается назначать те же блоки на те же потоки для лучшего использования кэш-памяти.
- `static_partitioner()` — распределяет блоки между потоками равномерно без динамического перехвата работы (аналог `schedule(static)` в OpenMP; удобен при однородной нагрузке).

### 7. Охарактеризуйте oneTBB parallel_for_each.
`tbb::parallel_for_each` (`#include <tbb/parallel_for_each.h>`) — шаблон параллельного алгоритма для обработки элементов контейнера или последовательности, заданной парой итераторов (`parallel_for_each(first, last, body)` или `parallel_for_each(container, body)`).

В отличие от `parallel_for`, алгоритм работает не только с индексируемыми диапазонами, но и с любыми итераторами ввода (`InputIterator`), например со списком `std::list`. Порядок обработки элементов не фиксирован, поэтому при изменении общих данных внутри `body` необходимо использовать средства синхронизации. Также алгоритм позволяет динамически добавлять новые элементы в работу через объект `tbb::feeder`.

---

### 8. В чем заключается особенность использования parallel_invoke?
`tbb::parallel_invoke` (`#include <tbb/parallel_invoke.h>`) предназначен для параллельного запуска небольшого заранее предопределённого числа независимых задач (традиционно от 2 до 10 аргументов; в современных версиях используется шаблон с переменным числом параметров).

Особенности:
- каждый аргумент должен быть вызываемым объектом без параметров (указателем на функцию, функтором с `operator()` или лямбда-выражением);
- возвращаемые значения вызываемых функций игнорируются;
- функция сама дожидается завершения всех переданных задач перед возвратом управления (явный вызов `wait` не требуется).

---

### 9. Что из себя представляет oneTBB task_group?
`tbb::task_group` — класс для организации одновременного выполнения группы задач. В отличие от `parallel_invoke`, число задач не фиксируется на этапе написания вызова: задачи можно добавлять динамически по мере выполнения (в циклах, рекурсивных алгоритмах и т. д.).

Основные методы класса:
- `run(f)` — добавляет задачу (функтор, лямбду или `task_handle`) в группу на асинхронное выполнение;
- `wait()` — ожидает завершения всех задач группы;
- `run_and_wait(f)` — запускает задачу и дожидается завершения всей группы;
- `cancel()` и `is_canceling()` — отмена невыполненных задач группы и проверка статуса отмены.

---

### 10. Что необходимо сделать для ожидания завершения задач при работе с oneTBB task_group?
Необходимо явно вызвать метод `wait()` у объекта `task_group` (либо запустить последнюю задачу через `run_and_wait(...)`). Ожидание обязательно должно быть выполнено до обращения к результатам задач и до разрушения объекта `task_group`, иначе при выходе из области видимости с незавершёнными задачами возникнет ошибка выполнения.

### 11. Приведите пример использования task_group и parallel_invoke.

**Пример `tbb::task_group` (рекурсивное вычисление чисел Фибоначчи):**
```cpp
#include <tbb/task_group.h>

int Fib(int n) {
    if (n < 2) return n;
    int x = 0, y = 0;
    tbb::task_group tg;
    tg.run([&] { x = Fib(n - 1); });
    tg.run([&] { y = Fib(n - 2); });
    tg.wait(); // ожидание завершения обеих задач
    return x + y;
}
```

**Пример `tbb::parallel_invoke`:**
```cpp
#include <tbb/parallel_invoke.h>

void f();
void MyFunction(int arg);

void RunInParallel() {
    tbb::parallel_invoke(
        f,
        [] { MyFunction(2); },
        [] { MyFunction(3); }
    );
}
```

### 12. Охарактеризуйте oneTBB parallel_reduce.
`tbb::parallel_reduce` (`#include <tbb/parallel_reduce.h>`) — шаблон параллельного алгоритма для выполнения операций редукции (свёртки) по диапазону: вычисления суммы, произведения, поиска минимума, максимума и т. п.

Диапазон рекурсивно делится на поддиапазоны, каждый поток накапливает частичный результат в локальном экземпляре (без гонок данных и блокировок), после чего частичные результаты объединяются ассоциативной операцией.

Предусмотрены две формы вызова:
1. **Императивная (класс или структурный объект `Body`):** `void parallel_reduce(range, body [, partitioner[, group]])` — использует объект с `operator()`, split-конструктором и методом `join`.
2. **Функциональная (лямбда-выражения):** `Value parallel_reduce(range, identity, func, reduction [, partitioner[, group]])` — принимает начальное (нейтральное) значение `identity`, лямбду обработки поддиапазона и бинарную операцию объединения результатов (например, `std::plus<double>()`).

### 13. Опишите класс для реализации редукционной операции oneTBB.
Класс-редуктор для `tbb::parallel_reduce(range, obj)` должен содержать следующие обязательные элементы:
1. **Поля данных**: указатель/ссылка на обрабатываемый массив (обычно в `private`) и публичное поле-аккумулятор (например, `double sum`).
2. **Основной конструктор**: сохраняет указатель на входные данные и инициализирует аккумулятор нейтральным значением (`0.0` для суммы).
3. **Конструктор разбиения (*splitting constructor*)** вида `ClassName(ClassName& r, tbb::split)`: вызывается при порождении подзадачи; копирует указатель на входные данные, а локальный аккумулятор инициализирует нейтральным значением.
4. **Оператор вызова `void operator()(const tbb::blocked_range<size_t>& r)`** (не `const`): обрабатывает поддиапазон `r` и **дописывает** результат к текущему аккумулятору (не сбрасывая его, так как один экземпляр может обработать несколько поддиапазонов).
5. **Метод `void join(const ClassName& rhs)`**: объединяет частичный результат `rhs` с текущим объектом.

Пример класса для суммирования элементов массива:
```cpp
class ReduceSum {
    const double* x_;
public:
    double sum;
    explicit ReduceSum(const double* x) : x_(x), sum(0.0) {}
    ReduceSum(ReduceSum& r, tbb::split) : x_(r.x_), sum(0.0) {}

    void operator()(const tbb::blocked_range<size_t>& r) {
        double local = sum;
        for (size_t i = r.begin(); i != r.end(); ++i)
            local += x_[i];
        sum = local;
    }

    void join(const ReduceSum& rhs) { sum += rhs.sum; }
};
```

### 14. Каким образом можно реализовать выполнение разнородных редукционных операций одновременно?
Чтобы вычислить несколько разных редукций за один проход по данным (например, одновременно найти минимум и максимум или минимум, максимум и сумму), все редуцируемые величины объединяют в один составной объект и передают в один вызов `tbb::parallel_reduce`. Есть два способа:

1. **На основе класса (или структуры) редуктора**:
   В классе объявляется несколько полей-аккумуляторов (например, `MinValue` и `MaxValue`). В основном и split-конструкторах каждое поле инициализируется своим нейтральным значением (`DBL_MAX` и `-DBL_MAX`), в `operator()` за один цикл по поддиапазону обновляются все поля, а в `join()` каждое поле объединяется своей операцией (`min` для минимума, `max` для максимума).

2. **На основе структуры результата и лямбда-выражений** (функциональная форма):
   Определяется структура, хранящая все нужные значения (например, `struct minmax_st { double v_min, v_max; }`), и бинарный оператор/лямбда объединения (`minmax_join`), применяющий к полям соответствующие операции (`min` и `max`). В `tbb::parallel_reduce` передаётся начальный экземпляр структуры, лямбда-обработчик поддиапазона и оператор объединения.
